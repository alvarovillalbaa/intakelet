## Dependency audit and proof limits

The actual runtime audit reports zero high/critical and two moderate findings
(uuid and its ExcelJS dependency effect), retained verbatim in
[audit JSON](qualified/runtime-dependency-audit.stdout.txt). The gate remains
`npm audit --omit=dev --audit-level=high`; it is not a clean/zero-advisory claim.
[GHSA-w5hq-g745-h8pq](https://github.com/advisories/GHSA-w5hq-g745-h8pq)
concerns caller-supplied output buffers/offsets in uuid v3/v5/v6. The SDK exposes
no UUID buffer API, but this does not establish complete dependency reachability
or remove the advisory. No vendor patch, ignored audit or automatic downgrade
was used. Hosts should retain this limitation when adopting the dependency set.

PDF pages without text, OCR errors, unsupported/legacy formats, complex document
fidelity, Windows/physical devices, real/private uploads, large-scale throughput,
general security isolation and durable host/provider integration are unproven.
The JavaScript heap budget is not a full OS sandbox. No paid provider, account,
credential copying, live app migration or authenticated extraction endpoint.
